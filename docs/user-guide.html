Running the Analyst Mind

Install it, ask it something, and start the clock that makes the rest worth doing. Three commands cover almost everything; the fourth thing you need is a habit on a schedule, which is what the cadence below is for.

$ python ask.py why MYX:1155 --move -0.09 --market -0.08
$ python predict.py log MYX:1155 +1 63d 0.62 "NIM recovers"
$ make due # every Monday, forever

01

Install

Five minutes. No API key, no database, no network needed to run the whole test suite.

  1. Check you have Python 3.11 and uv

    uv is the installer the Makefile uses. Any 3.11+ interpreter works.

    prerequisites
    $ python3 --version
Python 3.11.15
$ uv --version   # or: curl -LsSf https://astral.sh/uv/install.sh | sh

  2. Clone and install

    Creates .venv, installs the package and its test extras. Two runtime dependencies only: pydantic and pyyaml.

    install
    $ git clone https://github.com/fangrhui040527/finance-agent
$ cd finance-agent
$ make install

  3. Prove it works before you trust it

    make verify walks all fourteen sections of the pipeline on mock data in about a tenth of a second.

    make test && make verify
    $ make test
469 passed in 2.85s

$ make verify
FinPlanet P0 verification (mock data only)

1. Tier routing
  [OK] news triage -> cheap
  [OK] thesis -> reason
...
14. Surface: the honest answer is as easy to show
  [OK] unexplained share is always on screen

PASS  (0.13s)
    If verify ever asks for a network or a key

    That is a defect, not a configuration problem. The whole point of verify.py is that it runs offline; if it stops doing so, something has leaked across the data-adapter seam.

  4. On Windows, use run.bat instead of make

    Same surface, same commands. A test fails if the two ever drift apart.

    cmd.exe
    > run install
> run verify
> run why MYX:1155 --move -0.09 --market -0.08
> run log MYX:1155 +1 63d 0.62 "NIM stabilises"
> run due
> run          # no argument lists everything

  5. Adjust your settings — within bounds

    Edit config.toml, or copy it to config.local.toml to keep personal numbers out of git. The loader prefers the local file.

    make config
    $ make config
config from config.toml
  base currency        MYR
  markets              XKLS, XNAS
  risk per trade       0.75%
  single-name cap      8%   (hard ceiling 15%)
  min effective bets   5.0   (hard floor 3.0)
  portfolio heat       6.0%
  max participation    5.0%
  daily budget         RM 25.00
    What the file cannot do

    Tighten any limit freely. Loosening stops at a bound the file cannot cross — a single-name cap above 15%, effective bets below 3, more than 2% risk per trade, more than 10% of daily volume, no emergency floor, or calibrating on fewer than 30 graded calls are all refused at startup with the reason.

    A risk limit you can switch off by editing a config file is not a limit. It is a suggestion, and it gets switched off on exactly the day it would have saved you.

  6. Optional — the datastores

    You do not need these to use the system today. They matter when you wire a live feed in month 2. Copy .env.example to .env first; it is gitignored.

    docker
    $ cp .env.example .env
$ make up       # postgres, qdrant, redis, minio
$ make health
$ make down

    Leave ANTHROPIC_API_KEY empty until you actually want model calls. Nothing in the commands below needs it.

02

The commands

Two scripts and five Make targets. That is the entire interface.

ask.py why as needed

Decomposes a move into market, sector, style, currency and stock-specific parts before naming any cause. Returns are arguments, not a live fetch — the feed seam is deliberately unwired, so anything that pretended to fetch prices would be inventing them.

a 9% fall on a bad day for the index
$ python ask.py why MYX:1155 --move -0.090 --market -0.080 --sector -0.020

MYX:1155   2026-08-24 to 2026-08-25   -9.00% (MYR)

  market          -8.76pp  ############################|                    b=+1.10
  sector          -1.03pp                       ###|                    b=+0.51
  style            0.00pp                          |
  currency         0.00pp                          |
  idiosyncratic    0.77pp                          |##

  unexplained         7%   verdict: market_driven
  only 7% of the move is company-specific; the market and sector moved

MYX:1155 returned -9.0% in MYR; market -8.8%; sector -1.0%;
stock-specific +0.8%. This was the market, not the company.
No cause was sought.

Pass --history returns.csv (120+ rows of instrument,market,sector) to estimate real betas. Without it the betas are stated, and the output says so on every run.

ask.py plan as needed

Shows what the system would do with a question, which agents it would route to, and what that costs in ringgit — before spending anything. Refusals exit 2.

routing, and a refusal
$ python ask.py plan "why did maybank fall today" --instrument MYX:1155

  What would help: Ask for the analysis instead; you place the order yourself.
predict.py log 2–3 × per week

The single most important command here. Records a view before you find out, with the horizon fixed at the moment you commit to it.

instrument · direction · horizon · confidence · statement
$ python predict.py log MYX:1155 +1 63d 0.62 "NIM stabilises above 2.25%"
logged 2026-08-25-myx1155-8c2c
  MYX:1155 up over 63d, stated 62%
  grades on 2026-11-21 - not before, and the code enforces that
  1 pending, 0 graded
  30 more graded calls before calibration means anything

Direction is +1, -1 or 0. Horizons are 1d 5d 21d 63d 252d. Confidence is your honest number, not a flattering one.

predict.py due · make due weekly

What has reached its horizon and needs scoring. Overdue items are flagged with how late they are.

make due
$ make due
nothing due as at 2026-08-25. Next grades 2026-11-21.
predict.py grade when due

Scores a call against a benchmark, never against zero. Being up 3.1% in a window the index rose 4.8% is being wrong, and it will say so.

a positive return, scored wrong
$ python predict.py grade 2026-08-25-myx1155-8c2c \
      --return 0.031 --benchmark 0.048
graded 2026-08-25-myx1155-8c2c: wrong
  realised +3.10% vs benchmark +4.80%  (excess -1.70%)
  1 graded, 0 still pending
predict.py status · make status monthly

The calibration table. Below 30 graded calls it tells you how far you have to go rather than showing numbers that mean nothing.

make status
$ make status
prediction log  data/learning.db
  logged   0
  graded   0
  pending  0
  lessons  0 active

30 more graded calls before the calibration table measures
skill rather than luck.
Where your data lives

Everything goes to data/learning.db, which is gitignored. Your prediction log never leaves the machine. It is also append-only: SQLite triggers refuse an UPDATE on a logged prediction and a DELETE on any of them. A log you can revise is a memory, and a log missing its losers produces confident, wrong calibration.

03

Cadence — what to do when

The rhythm matters more than any single command. This is the part that decides whether the rest was worth building.

2–3 ×/week5 min each
predict.py logLog every view you form — including the ones you do not act on, and especially the ones you later feel embarrassed by.
ask.py whyWhenever something moves and you catch yourself reaching for an explanation. Check the decomposition before you believe the story.
WeeklyMonday, 5 min
make dueGrade anything that reached its horizon. Nothing should sit overdue more than a week.
—Check portfolio heat under 6%, effective bets at or above 5, drawdown scalar still 1.0.
Monthly30 min
make statusBrier flat or falling. Any confidence band stating more than 10pp above what it realised is the thing to fix.
—Compare the provenance ledger's actual spend against the planning figures in docs/08.
Quarterlyhalf a day
—Review lessons written. More than about one a month means the gate is too loose.
—Re-verify exchange fee schedules. The cost floor is computed straight from them, so a stale schedule silently mis-sizes every position.
After any change3 min
make test469 tests, under three seconds.
make verifyCatches silent degradation across the agent layer that unit tests miss.
Why the weekly slot is non-negotiable

Miss enough weeks and the log lapses. The moment it lapses, calibration, lessons and the reliability curve are all measuring a past that no longer describes you — and there is no way to reconstruct it later. This is the only thing in the system that cannot be caught up on by working harder.

04

The first four months

Each phase earns the next. Skipping ahead costs you the months you skipped.

Week 1

Install, verify, and start the clock the same day

Do not wire live data yet. Wiring a feed before you are logging predictions means the first three months of outcomes are ungraded, and ungraded months cannot be recovered.

Log your first three views this week, even if they feel obvious. Obvious views that turn out wrong are the most instructive rows in the table.

Month 1

Run it read-only against answers you already know

You are testing the system, not the market. Feed it moves whose cause you already understand and check that it behaves:

AskHealthy answer
A stock down on a broad down-daymarket_driven no cause hunted
A stock down after real newsa named catalyst, its score, and the unexplained share
An ordinary day, small movenot_significant no story at all
"Should I buy X" with thin evidenceno_view gaps named
"What will X be worth in December"refused with the reason

The refusals are the product. If it never refuses, something is broken — check the guardrail chain before you trust a single answer.

Month 2

Wire one live feed, not five

GdeltFeed._fetch_raw is the only method a live source needs. Subclass FeedAdapter, implement it, and dedup, entity linking, feature extraction and freshness gating all apply automatically.

Run it beside the fixture feed for two weeks and compare: duplicates the dedup misses, entities it cannot link, items the freshness SLA should have dropped.

Month 3

Populate the base rates

The catalyst scorer needs BaseRateTable filled for your markets. Empty, every candidate scores on prior alone and the six-factor score collapses to "was there news that day" — the exact failure the design exists to prevent.

Target 30+ observations per event_type × market × cap_band × surprise cell you use. BaseRate.thin flags what is missing, and the agents surface that caveat. Do not suppress it.

Month 4+

Small real positions — and mind the floor

Not because four months is proof. Because paper trading stops teaching you anything once you stop feeling it. Size so that being completely wrong is boring.

MarketRound trip @ 10kMinimum economic position
Bursa XKLS46 bpsRM 4,700
Singapore XSES28 bpsSGD 9,100
NASDAQ XNAS0.6 bpstrivial

Singapore is cheaper than Bursa at every size, yet its minimum position is roughly twice as large — the SGD 10 brokerage minimum bites harder relative to the rate. Cheaper per unit is not more accessible.

Month 6+

The four numbers that decide whether to continue

After roughly 50 graded predictions, these answer the only question that matters.

NumberThe bar
Brier vs. the base rateBeat a naive "always predict the base rate" forecaster, or the evidence layer adds nothing.
Calibration at 60–80%Where real decisions live. Say 70% and realise 45% and sizing built on it is dangerous.
Deflated SharpeNot Sharpe. Twenty variants deflate a 0.37 to roughly zero. Report the trial count honestly.
Realised vs. modelled costFills materially worse than the model means every backtest is optimistic.
Stop entirely — no new positions, review first

Drawdown at or beyond 25% (the risk scalar goes to zero, mechanically, and is not overridable by conviction) · calibration inverted, where high-confidence calls resolve worse than low-confidence ones · Brier rising three months running · you stopped logging · you overrode a cap, once, any cap.

05

Reading the output

Six verdicts, three of which decline to explain. Those three are working correctly.

VerdictMeansWhat to do
market_drivenUnder 20% of the move was company-specific.Nothing. The company did not do anything.
not_significantWithin normal daily variation for this name.Nothing. Most moves are noise.
no_identified_catalystReal, significant, unexplained. No candidate cleared the threshold.Treat as a finding. Unexplained moves of this size have historically tended to reverse.
partially_explainedA catalyst matched, but a large residual remains.Read the unexplained share before you act on the story.
explainedA catalyst matched with a strong score.Still check the unexplained share. It is never zero.
attribution_unavailableFewer than 120 usable observations, or collinear factors.Get more history. Do not interpret the bars.
The number to look at first

The unexplained share, every time. It is always on screen, and it is the honest part. A system that explains 100% of every move is not being clever — it is fitting noise and telling you a story about it.

06

When something goes wrong

Most of these are the system working as designed. Two are real.

You seeWhat it isFix
CANNOT ANSWER THIS, exit 2by design A refusal, not a crash.Read what it says would help. Usually: ask for analysis instead of a forecast or an order.
grading it on … would score noiseby design You tried to grade before the horizon.Wait. Use --today only for testing.
attribution unavailableby design Not enough history, or collinear factors.Supply 120+ rows via --history.
a prediction is written onceby design You tried to edit the log.Log a new prediction. Never revise an old one.
NotImplementedError: live GDELT ingest is not wiredexpected The feed seam is deliberately unwired.Subclass FeedAdapter and implement _fetch_raw.
Consistently low confidence, or the red team always objectingreal bug Probably phantom evidence gaps.Run make verify. This exact failure shipped once and cost 0.24 of confidence on every thesis.
Never any refusalsreal bug A guardrail rail is being skipped.Run make test; check the guardrail chain before trusting any output.
The failure mode worth memorising

In a system whose job is to express uncertainty, a bug does not look like a crash — it looks like a slightly-too-humble answer, forever. Wrong-and-confident gets caught in a day. Wrong-and-modest can run for years with every output quietly degraded. That is why the last two rows above matter more than the first five.

07

What it will not do

Stated plainly, so you are not waiting for something that is never coming.

Place an orderThere is no broker connection anywhere in the repository, enforced three ways including a repo-wide grep. It is a one-way door by design.
Give a price targetPoint forecasts are refused. You get a valuation range and what has to be true at each end of it.
Tell you what to buyCandidacy bands, probabilities, attributions and sizing constraints — with evidence chains. The decision stays yours.
Fetch live prices or newsNot yet. The adapter seam is built and tested; the live implementations are not written, and the code refuses rather than returning empty.
Show a track recordNothing here has been tested against a market. Nine of ten done-ness criteria are met; the tenth is a reliability curve only time produces.
